# 05. Plano de 90 dias

Um caminho enxuto para sair do nível 1 ou 2 com um primeiro ganho medido. Uma dor, uma equipe, um resultado.

## Dias 1 a 30: organizar

- [ ] Fazer o [autodiagnóstico](01-diagnostico.md) com 3 ou 4 pessoas de áreas diferentes e comparar as notas.
- [ ] Escolher **uma** dor usando a tabela de [03-ia.md](03-ia.md).
- [ ] Mapear os dados dessa dor com o modelo de [02-dados.md](02-dados.md): o que existe, onde está, quem é o dono.
- [ ] Definir o dono do tema e a lista de ferramentas aprovadas.
- [ ] Medir quanto tempo a tarefa leva hoje (linha de base).

## Dias 31 a 60: testar

- [ ] Criar o prompt ou agente para a dor escolhida (o [kit de prompts](https://github.com/peterrp21-cell/kit-prompts-engenharia) é um ponto de partida).
- [ ] Preencher a linha de governança desse uso em [04-governanca.md](04-governanca.md).
- [ ] Rodar com 2 ou 3 pessoas por 4 semanas, registrando tempo e erros.
- [ ] Ajustar o prompt a cada erro encontrado.

## Dias 61 a 90: decidir

- [ ] Comparar com a linha de base: o ganho é real, já descontando o tempo de revisão?
- [ ] Decidir: ampliar para mais pessoas, ajustar ou parar.
- [ ] Se ampliar, padronizar o dado de entrada para que a IA possa ler direto dos sistemas (próximo passo: nível 3, IA conectada).
- [ ] Escolher a próxima dor.

## Sinais de que está funcionando

- O ganho de tempo continua depois de descontar a revisão.
- A equipe usa sem precisar ser lembrada.
- Os erros da IA estão diminuindo porque o prompt e os dados melhoraram.
